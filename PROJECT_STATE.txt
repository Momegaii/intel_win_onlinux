Version: 0.5.0-resource-lifecycle
Target: Intel HD Graphics 4600 / Haswell GT2 / PCI 8086:0412

2026-11-20 physical Haswell PPGTT readiness audit:
Audited the Gen7.5 PPGTT model and DMA storage adapter against the Intel
Haswell PRM (Memory Views; Command Reference: Registers) and Linux v6.12 i915.
The audit confirms the two-level 4 KiB/1024-PTE/512-PDE geometry but found
four physical blockers: PDE and PTE address encodings differ (PDE bits 11:4 are
address 39:32; PTE bits 10:4 are address 38:32 and bit 11 is cacheability);
mapped pages are limited to 39-bit addresses while page tables may be 40-bit;
the page directory must reside in the GGTT and be written through GTTADDR; and
live PDE removal is unsafe because the hardware caches directory entries.
Register-level activation/invalidation (`PP_DCLV`, `PP_DIR_BASE`, per-engine
PPGTT enable, `INSTPM` TLB invalidate/sync flush, GGTT flush) is absent and all
involved registers remain i915-owned. No hardware state was changed, i915 was
not unbound, and no physical page walk is claimed. The evidence-separated plan
and minimal reversible experiment are in
`docs/design/HASWELL_GEN75_PHYSICAL_PPGTT_READINESS.md`. Stage 3 remains NOT
IMPLEMENTED; the next gate is review and correction of the software model,
not a hardware run.

Current eight-stage development sequence and evidence:
1. GPU resource read/write — COMPLETE for the i915-assisted path. On Haswell `8086:0412`, a Gen7.5 `MI_STORE_DATA_IMM` command wrote `0x2468ace0` at resource offset 16; CPU PREAD returned the exact value after GEM_WAIT. This does not establish IDW-owned execution.
2. Native DMA — IN PROGRESS. The QEMU EDU (`1234:11e8`) guest test passed under QEMU 11.1.3 TCG: 32 exact 4 KiB device-side DMA read/write round trips, owner/mask/descriptor rejection, and provider cleanup of an outstanding page during PCI remove. A second QEMU EDU run on QEMU 10.0.13 TCG with a Debian 6.12.117 guest passed page-table DMA layout verification and the full 32-cycle/remove sequence. Serial logs are preserved at `tests/qemu-dma/evidence-2026-11-20-tcg.log` and `tests/qemu-dma/evidence-2026-11-20-tcg-page-table.log`. This proves the Linux provider against QEMU's virtual PCI DMA implementation only. Physical Haswell DMA remains unproven and i915 remains bound. Required next proof: real DMA allocation/map/cleanup on an exclusively IDW-owned physical device.
3. Hardware PPGTT — NOT IMPLEMENTED. Required proof: the GPU uses IDW-created Haswell Gen7.5 page tables.
4. Independent submission — NOT IMPLEMENTED. Required proof: IDW submits and completes commands without i915 graphics execution.
5. Scheduler — NOT IMPLEMENTED. Required proof: multiple contexts, queues, timeout handling and recovery.
6. UMD — NOT IMPLEMENTED. Required proof: real shader compilation and rendering.
7. Display/KMS — NOT IMPLEMENTED. Required proof: an IDW-controlled display pipeline.
8. Ownership transition — NOT ATTEMPTED. Required proof: safely detach i915 and give IDW exclusive hardware control only after the independent backend is ready.

i915 remains bound and is the physical GPU owner. The CPU PPGTT model is not hardware page-table evidence; current GPU execution and address mappings are i915-assisted. Detailed Stage 1 results are recorded in `SESSION_LOG.md`.
