2026-11-20 corrected Haswell Gen7.5 PPGTT model:
Implemented separate PDE and PTE encoders. PDEs carry page-table address bits
39:32 at bits 11:4 and accept page tables below 2^40. PTEs carry page address
bits 38:32 at bits 10:4 and cacheability bit 3 at bit 11; mapped pages are
limited to 2^39. Reserved PDE bits and the 32 KiB page-size bit are rejected.
Added a GGTT-resident directory provider with GTTADDR PDE write/read, flush,
and release callbacks. The model keeps a separate CPU shadow. Unmap keeps the
PDE valid; quiesced reclaim points it at a zeroed scratch table, and the old
table is freed only after the next invalidation completes. PDE publication and
reclamation are rejected while active; invalidation failure still poisons the
VM. Hand-derived golden vectors, ASan/UBSan, contract/adapter/memory-manager
tests, GCC W=1 kernel builds, and a corrected QEMU EDU page-table run passed.
No hardware state was changed. i915 remains bound and is the physical GPU
owner. Stage 3 remains NOT IMPLEMENTED: there is no hardware GGTT aperture
allocator, MMIO GTTADDR path, real register-level invalidation, VM activation,
or physical page-walk evidence. The Stage 3B closure audit added page-table DMA
synchronization, RING_MODE_GEN7 save/restore, pre-enabled rejection, exact
simulated ordering, and a NO-GO readiness matrix; cache policy and PP_DIR_BASE
load-completion ordering remain blockers. Details:
docs/design/HASWELL_GEN75_PHYSICAL_PPGTT_READINESS.md and
docs/design/HASWELL_GEN75_STAGE3B_PHYSICAL_READINESS_MATRIX.md.

2026-11-20 physical Haswell PPGTT readiness audit:
Audited the Gen7.5 PPGTT model and DMA storage adapter against the Intel
Haswell PRM (Memory Views; Command Reference: Registers) and Linux v6.12 i915.
The audit confirmed the two-level 4 KiB/1024-PTE/512-PDE geometry and found
four CPU-model blockers: PDE and PTE address encodings differ (PDE bits 11:4 are
address 39:32; PTE bits 10:4 are address 38:32 and bit 11 is cacheability);
mapped pages are limited to 39-bit addresses while page tables may be 40-bit;
the page directory must reside in the GGTT and be written through GTTADDR; and
live PDE removal is unsafe because the hardware caches directory entries.
Those software findings are corrected in the newer model entry above.
Register-level activation/invalidation (`PP_DCLV`, `PP_DIR_BASE`, per-engine
PPGTT enable, `INSTPM` TLB invalidate/sync flush, GGTT flush) remains absent and
all involved registers remain i915-owned. No hardware state was changed, i915
was not unbound, and no physical page walk is claimed. The evidence-separated
plan and minimal reversible experiment are in
`docs/design/HASWELL_GEN75_PHYSICAL_PPGTT_READINESS.md`. Stage 3 remains NOT
IMPLEMENTED; the next gate is exclusive-ownership and real GGTT/MMIO work, not
a hardware run.
